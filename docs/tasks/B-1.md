# Б-1. Инфраструктура и каркас бэкенда

Папки: infra/, backend/, pipeline/load.py (+ pipeline/__init__.py), .github/workflows/.

1. infra/docker-compose.yml: postgres:16 (БД создаётся с локалью ru_RU.UTF-8 или en_US.UTF-8 — см. contracts/README.md, иначе pg_trgm не ищет по кириллице), backend (FastAPI), frontend (nginx отдаёт собранный frontend/dist и проксирует /api на backend). infra/.env.example со всеми переменными: DATABASE_URL, YC_FOLDER_ID, YC_API_KEY, S3_BUCKET, S3_ACCESS_KEY, S3_SECRET_KEY.
2. backend/: FastAPI + SQLAlchemy 2, при старте применяет contracts/schema.sql (идемпотентно), GET /api/health. Структура: backend/app/main.py, backend/app/db.py, backend/app/routers/, backend/app/search/ (пустой пакет с заглушкой search(filters) — его пишет другой человек), backend/tests/.
3. pipeline/load.py: читает contracts/fixtures/ (или путь из аргумента) и пишет в БД идемпотентно (повторный запуск не дублирует).
4. infra/deploy.sh: rsync на VM по SSH + docker compose up -d --build. Раздел README «Запуск локально и на VM».
5. .github/workflows/ci.yml: ruff + pytest для backend и pipeline на каждый PR; postgres как service container.

Готово, когда: docker compose up поднимает всё, python -m pipeline.load загружает фикстуры, /api/health отвечает 200, pytest зелёный (тест: загрузка фикстур дважды даёт то же число строк).
