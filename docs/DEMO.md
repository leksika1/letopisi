# Демонстрация жюри: 6 минут 30 секунд

[Вход в проект](../README.md) · [Метод](METHOD.md) · [Данные и качество](DATA.md) · [Запуск](DEPLOY.md)

Цель показа: запрос → таблица → проверяемый источник → решение специалиста → выгрузка. Каждый критерий оценивается жюри по шкале 0–5; сценарий даёт проверяемые примеры, а не обещает баллы. Названия элементов и числа ниже — по проверенным фактам стенда из задания на **22.11.2026**; перед выступлением сверьте их снова.

## Подготовка перед показом

- [ ] Открыть http://51.250.9.93:8000/ без VPN; проверить сеть площадки и `/api/health`.
- [ ] Заготовить вкладки: поиск по лосю, встреча 19.02.2020, PDF стр. 499, фенология герани, публикация, [METHOD](METHOD.md), подготовленный отчёт качества.
- [ ] Прогреть запрос по лосю и изображение страницы 499; проверить предупреждение «2022 → 2020». Облачный ключ нужен лишь для запросов, которым не хватило правил.
- [ ] Сбросить старые фильтры и статус; проверить четыре кнопки примеров. На главной есть вкладки «Все фильтры / Вид / Автор / Фенология / Место» и полная панель фильтров.
- [ ] Зафиксировать числа: по брифу — 6278 записей книги 2020 и 5 тестовых 1995; выяснить, завершён ли OCR 1995/1996. Без подтверждения говорить «тестовая выборка».
- [ ] Заполнить поле «Проверяющий». Для правки подготовить отдельную тестовую запись; на научной записи показать форму без сохранения. «Верно» нажимать после фактической сверки.
- [ ] Скачать XLSX/CSV и проверить 15 колонок; подготовить короткое видео и скриншоты таблицы, карточки, оригинала, фенологии и истории. Эти материалы готовятся отдельно, в репозитории их нет.
- [ ] Поднять локальный резерв с оригиналами и данными из `release/` по [DEPLOY](DEPLOY.md). Проверить заранее: фикстуры дают другие числа, чем стенд.
- [ ] Подготовить проверенный пример ошибки: лишние «лососевые» в поиске «лось» или форма «4 особей»; если исправлено — выбрать другую подтверждённую ошибку. Отдельно подготовить флаг места у выбранного лося, список неподдерживаемых страниц и `data/quality.json`, если он рассчитан. Не полагаться на страницу «Качество»: API ещё в работе.

## Если что-то сломалось

| Сбой | Запасной ход |
|---|---|
| Стенд не открывается | Отключить VPN, открыть проверенный локальный `http://localhost:8000/`; назвать показанную базу |
| Нет интернета/облака | Локальная база и четыре готовых набора фильтров не требуют LLM; облачный OCR во время показа не запускать |
| Обычный запрос не разобрался | Нажать кнопку примера или задать вид, годы и тип вручную; показать фильтры и пояснить сбой разбора |
| Не загрузился PDF | Открыть сохранённый оригинал на стр. 499; рядом — скриншот подсветки, назвав его резервным материалом |
| Локальный запуск тоже недоступен | Подготовленное видео, скриншоты и выгрузка; явно назвать их записью предыдущего запуска |
| Страница «Качество» пуста | Рассчитанный JSON и METHOD; без отчёта — контрольный эталон и ограничения без новых чисел |

Не начинайте установку зависимостей, полный прогон или развёртывание во время выступления.

## Чего не показывать / известные ограничения

- Не представлять 1995/1996 как полностью обработанные книги без подтверждения. Статус документа сам по себе не доказывает полноту.
- Не обещать автоматическое «загрузили файл — получили базу»: UI сохраняет `queued`, воркер пока заглушка. Цикл MVP показываем на заранее обработанной книге; CLI и загрузка результатов описаны отдельно.
- Не использовать «Качество» как готовый экран: `/api/quality` пока 404. Метрики фикстур — заглушки; P=1,0/R≈0,91 относится к прежней контрольной проверке без LLM, не всей книге.
- Не делать карту главным сценарием: координаты расширенного справочника ещё не загружаются в БД, точек почти нет.
- Не утверждать, что поиск не ошибается: «лось» иногда находит «лососевые»; известна форма «4 особей». Планы — [CORE-fixes](tasks/CORE-fixes.md).
- Не выдавать `confidence` за вероятность правильности, флаг за доказанную ошибку, а 6273 записи архива за число записей текущей БД.
- Не выдавать редизайн из [DESIGN](DESIGN.md) за реализованный интерфейс. Рукописные пометки, рисунки и сложные слитые таблицы не обещать распознавать без ошибок.

## Ответы на вероятные вопросы жюри

| Вопрос | Короткий ответ |
|---|---|
| Какое качество OCR старых книг? | Vision OCR по половинам разворота, сохраняем страницу и координаты. Полной независимой оценки сканов ещё нет; OCR 1995/1996 нужно завершить и проверить вручную. |
| Как защищаетесь от галлюцинаций LLM? | Схема, контекст, обязательная цитата; ищем её в тексте и отдельно проверяем дату/число. Без совпадения — флаг и снижение confidence. Это делает риск видимым, но не гарантирует смысловую правильность поля. |
| Сколько стоит обработка? | Прогон 2020: около 1,5 тыс. ₽, 29 минут, 1031 LLM-запрос. OCR сканов и инфраструктура сюда не включены. Кэш экономит на повторной обработке неизменного входа. |
| Как масштабировать на 27 книг? | Контракт и загрузка по документам, кэш, ограниченная параллельность, правила повторяющихся таблиц. Сначала пилотные страницы и оценка объёма сканов; время и стоимость нельзя просто умножить на 27. |
| Можно ли править вручную и кто отвечает? | «Верно / Исправить / Отклонить», «Проверяющий», история old/new и статусов. Имя вводится вручную, это не полноценная аутентификация. Источник не меняется. |
| Как ищутся синонимы и старая латынь? | Через accepted/synonym/variant, леммы и нечёткое сопоставление; исходное имя сохраняется. Обогащённые CSV есть, но не все загружены в БД стенда, покрытие ограничено. |
| Как добавить новую книгу? | Текущие книги: оригинал → ingest/OCR → pipeline.run → комплект → load.py. Новую книгу надо зарегистрировать в метаданных, проверить структуру, страницы и справочники. CLI пока ищет документы в фикстурах; одной загрузки через UI недостаточно. |
| Насколько точны метрики? | Контрольный эталон — 22 записи, он не представляет всю книгу. Нужна независимая полная разметка страниц разных типов и одинаковая область оценки; отчёт фиксирует версию эталона. |
| Почему столько флагов и что означает confidence? | Чаще вид не найден в стартовом справочнике. Confidence — эвристика стратегии и штрафов для очереди проверки; 74% с флагами не означает 74% неверных записей. |
| Почему в книге 2020 годы 2018–2019 и замена 2022? | Годы наблюдений взяты из колонок и отделены от года книги. «2022» — известная опечатка примеров кейса; замена на 2020 видна в предупреждении и может быть исправлена фильтрами. |
