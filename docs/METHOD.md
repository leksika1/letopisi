# Метод извлечения записей из летописей природы

Цель — превратить страницы летописи в записи по шаблону заповедника (13 колонок) так, чтобы
**каждое значение можно было проверить по оригиналу**, а то, чего в тексте нет, оставалось пустым.
Код ядра — `pipeline/` (`python -m pipeline.run --document 3`).

## 1. Текст и координаты

- **PDF с текстовым слоем** (книга 2020): блоки и строки PyMuPDF с координатами; таблицы —
  `page.find_tables()`, каждая строка таблицы — отдельный фрагмент «Заголовок: значение; …».
  Если таблица продолжается на следующей странице без шапки, шапка наследуется.
- **Сканы** (книги 1995, 1996 — развороты): OCR Yandex Vision по половинам разворота
  (загрузчик `pipeline/ingest`, задача Б-2). Ядро работает с любым источником одинаково: вход —
  фрагменты (chunks) с текстом и положением на странице.
- Координаты строк хранятся рядом с фрагментами; по ним рамка цитаты рисуется на картинке страницы.

## 2. Разделы

Оглавление (стр. 3–4) разбирается в дерево «7.3 Сезонная динамика растительных сообществ → стр. 69».
Для каждой записи оглавления находится сам заголовок на странице, поэтому страница, где кончается
один раздел и начинается другой, делится точно. Строка под заголовком вида «Поликарпова Н.В.,
Бычков Ю.М, …» — авторы раздела. Подзаголовки с авторами внутри глав («1. ОСОБЕННОСТИ ЭКОЛОГИИ
МЕЛКИХ МЛЕКОПИТАЮЩИХ / Крюкова С.А.») становятся подразделами. Без оглавления (сканы) заголовки
ищутся по шаблонам: «N.N Название», «N. ЗАГЛАВНЫЕ», короткая строка без точки, строка перед авторами.

## 3. Маршрутизация: правила там, где структура известна, LLM — для свободного текста

| Что | Как | Почему |
|---|---|---|
| «Сравнительная хронология зацветания» (вид × годы) | парсер: запись на каждый год, год = заголовок столбца, «зацветание» = фаза 5 | 100 % воспроизводимо, даты 2018–2019 получают свой год |
| Календарь природы | парсер: дата наступления; многолетние средние и крайние даты — в примечание | погода/лёд/снег → `env_measurement` |
| «Вид × номер фенофазы» (табл. 7.11–7.12) | парсер: запись на каждую фазу, местообитание — строка-группа, топоним — из заголовка таблицы | шкала 1–16, 10а/10б |
| Учёты «вид × число/маршрут» | парсер: запись на каждую числовую ячейку, показатель = заголовок столбца | «32/22», «0,45» |
| Подписи к фото «Рисунок … – Вид. Место, дата. Фото: Автор» | парсер | вид + место + дата + наблюдатель |
| Остальной текст, неизвестные таблицы | LLM | дневники встреч, очерки, библиография |

Разделы без наблюдений (введение, просвещение, культурное наследие, международное сотрудничество,
приложения) в LLM не отправляются (`--all-sections` отключает это).

## 4. LLM со схемой и обязательной цитатой

YandexGPT / Qwen3 через OpenAI-совместимый API Yandex AI Studio, `temperature = 0`, ответ строго
по JSON-схеме (если модель не поддерживает — `json_object` + проверка pydantic + один повтор с
текстом ошибки). Инструкция: одна запись = объект × дата; **дословная минимальная цитата** для
каждой записи; значения, которых нет в тексте, — `null`; дата как в тексте; наблюдатели — только
названные в тексте. Контекст: книга и год, раздел и его авторы, страница, предыдущий абзац,
заголовок таблицы. Три примера взяты из эталонных фикстур (фенология растения, учёт лосей, погода).
Несколько соседних абзацев одного раздела отправляются одним запросом (до 2500 символов).
Ответы кэшируются на диске: повторный прогон бесплатен; токены пишутся в журнал.

## 5. Привязка к оригиналу

Цитата ищется в тексте фрагмента точно, затем после нормализации (пробелы, переносы «сло-\nво»,
ё/е, тире), затем нечётко (rapidfuzz, сходство ≥ 90). Найденная цитата **заменяется дословным
текстом источника**, сохраняется интервал `quote_span` и рамки строк `bboxes` — интерфейс
подсвечивает именно этот фрагмент страницы. Не нашли — флаг `quote_not_found`, достоверность падает.
Так «галлюцинация» модели становится видимой: значение без опоры в тексте не выглядит надёжным.

## 6. Нормализация по справочникам

- **Даты**: «12.05», «20.10.19», «12–15.06», «с 30 по 31 марта», «в первой декаде июня»,
  «в конце мая», «весной», «зимой 1995/96» → интервал `date_from…date_to` и точность
  (день/декада/месяц/сезон/год/интервал). Год — из даты, иначе из столбца таблицы, иначе год книги.
- **Виды**: точное имя → латинский бином (в т. ч. синонимы: *Ledum palustre* → *Rhododendron
  tomentosum*) → леммы всех слов («герани лесной» → «герань лесная») → нечётко ≥ 90. Только род или
  «лебедь» без вида — запись привязывается, но с флагом `taxon_ambiguous`.
- **Места**: варианты из каталога + склонения («Калкупи» → Калкупя, «Ворьеме» → Ворьема),
  финские формы на -ярви/-йоки не склоняются; родовое слово проверяется по категории
  («озеро Каскама» ≠ гора Каскама). «В заповеднике» → «Пасвик».
- **Люди**: «Хохлов, Сметанников, Шершнев», «А. М. Хохлов … и В. Е. Шершнев», «Валовой Е.В.»
  (падеж) → каталог сотрудников; «Сметанников» и «Сметанникова» различаются. Если в тексте
  наблюдателя нет — подставляются авторы раздела с пометкой «наблюдатель по автору раздела».
- **Фенофазы**: явный номер («фаза 12») или ключевые слова (зацветание, массовое цветение,
  листопад, прилёт, первая песня, выход из берлоги, кладка, выводок, отлёт) по шкале книги 2020.

## 7. Флаги и достоверность

Флаги: `quote_not_found`, `value_not_in_quote` (числа нет в цитате), `date_not_in_quote`,
`date_ambiguous`, `year_outside_book` (информативный: год наблюдения ≠ год книги),
`taxon_unmatched/ambiguous`, `place_unmatched`, `person_unmatched`, `low_ocr`, `table_parse_uncertain`.
`confidence = база − штрафы`: база — парсер таблицы 0.95, подпись к фото 0.92, LLM 0.85; штрафы —
0.35 за ненайденную цитату, 0.25 за число не из цитаты, 0.20 за дату не из цитаты / низкий OCR /
неуверенный разбор таблицы, 0.10 за неоднозначную дату или вид, 0.05 за место/человека не из
каталога, нечёткую привязку цитаты или наблюдателя по автору раздела (`pipeline/flags.py`).
Записи с флагами попадают на экран «На проверку».

## 8. Оценка качества

`python -m pipeline.eval.evaluate --gold gold/<файл>.csv` сопоставляет эталон (формат
`gold/template.csv`) с извлечёнными записями (документ + страница ±1 + вид + дата + совпадение слов
цитаты) и считает precision/recall/F1 по полям: дата, год, вид (рус./лат.), топоним, местообитание,
численные, фенофаза, наблюдатель, страница; примеры ошибок (пропуск / лишняя / неверное значение)
и список неподдерживаемых страниц — в `data/quality.json` (`GET /api/quality`).

Сейчас есть только контрольный эталон `gold/sanity_2020.csv` (22 записи, размечены вручную:
табл. 7.10 на стр. 69 и млекопитающие на стр. 449–450). Без LLM (ключа не было) извлечено 20 из
22: precision 1.0, recall 0.91. Обе пропущенные записи взяты из свободного текста, его разбирает
только LLM. Это проверка, что механизм работает, а не оценка качества: для неё нужна разметка
страниц целиком (`--scope page`).

## 9. Ограничения и что не поддерживается

- Сканы 1995/1996 обрабатываются только после OCR. Рукописные пометки и рисунки не распознаются.
  Страницы-картинки в книге 2020 (стр. 471, 611, 620, 629) попадают в список неподдерживаемых.
- Сложные таблицы со слитыми ячейками (например, учёт птиц на стр. 157) `find_tables` разбирает
  неточно. Такие строки уходят в LLM с флагом `table_parse_uncertain`, а когда заголовков столбцов
  нет, значения могут оказаться не в своих столбцах.
- Стартовый справочник видов содержит 32 вида, поэтому большинство видов книги получают
  `taxon_unmatched`, пока нет полного справочника (`dictionaries/taxa.csv`, задача Б-4).
- Связи между предложениями («там же», «этим же наблюдателем») модель видит только через
  предыдущий абзац. Место из предыдущей записи не подставляется — это сделано намеренно, чтобы
  ничего не додумывать.
- Публикации внутри текста (ссылки «Ивантер, 1975») не извлекаются. Записями становятся только
  элементы библиографии и раздела «Научные исследования».
