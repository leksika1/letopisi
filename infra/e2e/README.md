# Сквозные проверки «Цифровых Летописей природы»

Набор поднимает FastAPI на Uvicorn и отдаёт производственную сборку React через отдельный процесс nginx. Браузер Chromium, HTTP-клиент и штатные CLI работают с одноразовыми базами PostgreSQL 16 и временными оригиналами документов. Ключи облачных сервисов для прогона не нужны. Для OCR используется ответ из дискового кэша, для LLM — штатный тестовый ответ. Прогон опубликованной книги использует архивы репозитория.

## Запуск

Нужны Python 3.12, Node.js 24 с npm, nginx, PostgreSQL 16 с `pg_trgm` и роль с правом `CREATEDB`. Из корня репозитория выполните:

```sh
npm --prefix frontend ci
npm --prefix frontend run build
python -m pip install -r infra/e2e/requirements.txt
python -m playwright install chromium
export TEST_DATABASE_URL='postgresql+psycopg://postgres@127.0.0.1:5432/postgres'
python -m pytest -q infra/e2e
```

В `TEST_DATABASE_URL` укажите адрес своего тестового PostgreSQL. Если nginx отсутствует в PATH, задайте полный путь к исполняемому файлу в `NGINX_BIN`. Для уже установленного Chromium или Edge задайте `E2E_CHROMIUM`. На Windows переменные задаются через `$env:ИМЯ='значение'` в PowerShell. На чистой Linux-машине Playwright также может потребоваться установка системных библиотек командой `python -m playwright install --with-deps chromium`.

Тестовый стенд подставляет адреса loopback и свободные порты в `infra/nginx.conf`. Временные БД удаляются после прогона. Для проверки «загрузка → поиск» ожидание обработчика по умолчанию составляет 15 секунд. Значение можно изменить через `E2E_PROCESSING_TIMEOUT`. Браузерные тесты проверяют данные карты из API, внешние растровые тайлы в эту проверку не входят.

## Что проверяется

| Путь | Проверяемый результат |
|---|---|
| HTTP-контракт | Реальные запросы к 17 операциям OpenAPI. Методы, пути, статусы, JSON-схемы и типы файлов сверяются с контрактом. Перечень групп тестов сверяется со всеми `operationId`. |
| Поиск и аналитика | Четыре запроса жюри, подсказки, фильтры, пагинация, фенология и виды по месту. Вопрос о лосе проверяет предупреждение о замене 2022 года на 2020, сохранённые фильтры и порядок записей после перезагрузки и переходов по истории браузера. |
| Браузер | Все шесть объявленных экранных маршрутов, переход на неизвестный путь, пять вкладок поиска, клавиатурная навигация, редактирование, журнал, загрузка и скачивание. |
| Файл и источник | Оригинальные байты PDF/DOCX/XLSX и имя файла, PNG страницы, диапазон цитаты и координаты подсветки. В синтетической книге браузер открывает фактически извлечённое наблюдение и увеличивает фрагмент. |
| Импорт и извлечение | PDF с текстовым слоем, скан с OCR-кэшем, DOCX, XLSX и CSV. Для поддерживаемых книг данные проходят CLI, сборку комплекта, два импорта, поиск и карточку. |
| Справочники | Штатные CLI GBIF и геокодера получают ответы из кэша. Нормализатор использует сгенерированные CSV для конкретного наблюдения. |
| Релиз | Архивы книги 2020 года дают 6 273 наблюдения этого тома. Повторная загрузка добавляет ноль строк. Оценщик формирует валидный отчёт по 22 строкам эталона. |
| Повторное извлечение | Вся книга вновь проходит через `pipeline.run`. Набор сравнивает ссылки на источник, цитаты, их границы и координаты всех 6 273 записей с опубликованным архивом. Все 1 042 окна LLM обслуживает кэш. Отдельный тест запускает `quick_chunks` для абзаца и таблицы. |
| HTTP-клиент модели | Локальный сервер отвечает SDK через HTTP. Проверяются переход с `json_schema` на `json_object`, исправление невалидной записи и повторный запуск пайплайна из кэша без сетевых обращений. |
| Сбои и параллельные запросы | Отказ и восстановление соединения с отдельной БД, два одновременных изменения записи и одна история правок, две конкурентные загрузки одинаковых байтов и откат загрузчика при конфликте оригиналов. |
| Обновление существующей базы | Сервис стартует с данными схемы v1.0. Через nginx проверяются прежняя карточка, цитата и журнал правок, а также новые поля v1.1. |
| Развёртывание оригиналов | ZIP с переименованным PDF, пустой книгой и посторонним приложением. Импорт сверяет SHA-256 с реестром документов, повторно использует целые файлы и сообщает об испорченной локальной копии. |

Отдельная проверка для одноразовой Linux-VM вызывается командой `bash infra/e2e/test_vm.sh --disposable user@qa-vm`. Она запускает штатный деплой и проверяет стенд через SSH-туннель. Нужны SSH, rsync, Bash и Docker Compose на целевой VM. SSH-сервер должен разрешать локальное перенаправление порта к 127.0.0.1:8000. После проверки развёрнутый стенд доступен на ней для осмотра.

## Измерение покрытия исходного кода

Для Python измеряются строки и ветви `backend/app`, `pipeline`, `dictionaries/scripts` и `infra/import_originals.py`, включая дочерние процессы. Конфигурация объединяет измерения временных копий пайплайна. Для TypeScript исходники приложения получают счётчики Istanbul перед преобразованием Vite. Тесты, объявления типов и моки фронтенда исключены. Обычный E2E-прогон использует сборку без счётчиков.

Из корня репозитория с теми же переменными подключения:

```sh
npm --prefix infra/e2e/coverage-ui ci --ignore-scripts
export E2E_UI_MEASUREMENT="$(mktemp -d)/report"
node infra/e2e/coverage-ui/measure.mjs build "$E2E_UI_MEASUREMENT"
export COVERAGE_RCFILE="$PWD/infra/e2e/coverage.ini"
export COVERAGE_FILE="$E2E_UI_MEASUREMENT/python.coverage"
python -m coverage run -m pytest -q infra/e2e
python -m coverage combine
python -m coverage report
node infra/e2e/coverage-ui/measure.mjs report "$E2E_UI_MEASUREMENT"
```

Команды формирования отчётов можно выполнить и после красного прогона. Покрытие строки означает, что она выполнилась, включая выполнение в тесте, обнаружившем дефект.

## Результат прогона 22 ноября 2026

Из 62 сквозных тестов прошли 52, упали 10, пропущенных нет. Десять падений соответствуют восьми дефектам ниже. По HTTP вызваны все 17 операций OpenAPI, для 16 получен предусмотренный контрактом успешный ответ. В браузере открыты все шесть маршрутов приложения.

| Исполняемый код | Строки | Ветви |
|---|---:|---:|
| Python, 61 файл | 4 694 / 5 418 (86,6%) | 1 589 / 2 136 (74,4%) |
| TypeScript, 26 файлов | 595 / 669 (88,9%) | 728 / 1 022 (71,2%) |

Отдельно прошли 227 существующих тестов Python и 23 теста Vitest, а также TypeScript strict и производственная сборка. Проверки Ruff из CI и проверки нового кода через Ruff и mypy прошли. Общая проверка Ruff каталогов `backend pipeline dictionaries infra` нашла 49 замечаний в файлах, которых изменения ветки не касались.

Обычная производственная сборка и сборка со счётчиками дали одинаковые результаты для всех 62 тестов. Стенд для этих прогонов обрабатывал запросы через настоящий nginx. Облачные OCR, LLM и геокодер проверены на воспроизводимых сохранённых или локальных ответах.

## Воспроизводимые дефекты

| Дефект | Проверка и наблюдаемый результат |
|---|---|
| Отчёт качества | `test_quality_report` получает HTTP 404 с фильтром книги и без него. `test_quality_screen_renders_metrics` подтверждает, что экран не показывает метрики. Отдельный тест запускает оценщик и успешно проверяет сформированный JSON. |
| Ссылка из CSV | При закрытии карточки, открытой по экспортной ссылке с `?page=76`, поиск показывает «стр. 76 из 1» и пустую таблицу. |
| Большая очередь проверки | API возвращает 516 записей в тестовом наборе, экран показывает первые 500. До остальных по очереди перейти нельзя. |
| Карта полной книги | Проверка сравнивает число мест в интерфейсе с количеством различных мест в БД для той же выборки. Книгу загружают из опубликованного архива. |
| Смена типа записи | Форма отправляет тип «публикация» и её реквизиты, но оставляет прежний тип объекта. Сервер отвечает 422. |
| Вложенная таблица DOCX | Строка внутренней таблицы отсутствует в JSONL. Тест проверяет сохранность текста без предположений о будущей нумерации. |
| Привязка цитаты | Извлекатель принимает слово «полёвки» за источник целого предложения модели и сохраняет запись без флага `quote_not_found`. |
| Загрузка нового документа | После успешного HTTP 201 DOCX остаётся `queued`, поиск по нему пуст. Вызов фонового обработчика в Б-3 пока реализован как заглушка. |

При сортировке по дате карта читает первые 500 результатов. В полной книге это даёт 4 из 31 встречающегося идентификатора места. Координаты есть у двух из этих четырёх, и экран показывает «2 из 4». Отдельное ограничение связано со справочниками. Импорт комплекта стенда использует контрактные JSON-справочники. В БД координаты есть у 3 мест, в обогащённом CSV — у 17. Например, API возвращает пустые координаты реки Паз. Аналогично наблюдение с таксоном, существующим только в обогащённом CSV, не загружается в такой комплект из-за ограничения внешнего ключа.

На PostgreSQL 16.6 для Windows дополнительно проверена база с локалью `C`. Когда `pg_trgm` не распознаёт кириллицу, диагностическая строка схемы вызывает `current_setting('lc_ctype')` и останавливает старт сервиса с ошибкой отсутствующего параметра. На Windows тесты работали с локалью `en-US`. Compose задаёт `en_US.utf8`.
