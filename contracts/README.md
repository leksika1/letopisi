# contracts/ — единый контракт проекта

Контракт, по которому параллельно работают пайплайн (извлечение), бэкенд (БД + API) и фронтенд.
Источник требований — `docs/SPEC.md`. Имена полей и типы одинаковы во всех файлах ниже;
`validate.py` проверяет это автоматически.

## Файлы

| Файл | Что внутри | Кто пользуется |
|---|---|---|
| `observation.schema.json` | JSON Schema 2020-12. Корень — запись `Observation`. В `$defs` лежат все остальные сущности: `Locator`, `Chunk`, `Document`, `Section`, `Taxon`, `TaxonName`, `Place`, `PlaceName`, `Person`, `Phenophase`, `ObservationEdit`, `ObservationPatch`, `SavedQuery`, `SearchFilters`, `Quality` и др., а также все enum | все |
| `schema.sql` | PostgreSQL 16+: таблицы, PK/FK, CHECK для enum, jsonb, индексы pg_trgm. Скрипт идемпотентен | бэкенд, пайплайн |
| `openapi.yaml` | OpenAPI 3.1: все эндпоинты `/api/...` из SPEC, параметры, тела запросов и ответов, пагинация, ошибки. Схемы данных не дублируются: они подключаются через `$ref` на `observation.schema.json` | бэкенд, фронтенд |
| `export_columns.json` | Колонки выгрузки по порядку: `{header, source, rule}`. 13 заголовков шаблона + «Источник (ссылка)» + «Достоверность» | бэкенд |
| `fixtures/` | Тестовые данные, валидные по схеме (см. ниже) | все: сиды БД, моки API, тесты |
| `gen_fixtures.py` | Собирает `fixtures/` из `data/raw` (цитаты и bbox — из текстового слоя PDF) | владелец ядра |
| `validate.py` | Проверка всего контракта | все, перед каждым PR |
| `../gold/template.csv` | Заголовок эталонной разметки: 13 колонок шаблона + «PDF-страница» + «Документ» + «Цитата». UTF-8 с BOM, разделитель `;` | разметчики, `/quality` |

Какие случаи покрыты в `observations.jsonl`:
- **Табл. 7.10.** Строка «Герань лесная» дала 3 записи: 2020, 2019 и 2018 годы. Год наблюдения отличается от года книги — у таких записей флаг `year_outside_book`. Отдельной записью — береза пушистая.
- **Календарь природы.** Зацветание герани, снежный покров и ледостав (`env_measurement`), первая встреча медведя, прилёт лебедя и пуночки, первая песня большой синицы, первое кукование кукушки.
- **Табл. 7.11.** Фенофаза 5 герани лесной. На этой записи показана правка (`status=edited`).
- **Лось.** 10 записей (8 за 2020 год, 1 за 2019, 1 за 1995). **Бурый медведь** — 3 наблюдения и 1 публикация.
- **Заяц-беляк, ЗМУ 1995** — 3 записи по примеру из листа `шаблон_животные`. Одна из них `verified`. К ним — высота снега за 1995 год.
- **Публикации.** Статья о буром медведе (раздел 10) и 2 записи из «Библиографического списка».
- **Примеры флагов:** `quote_not_found`, `value_not_in_quote`, `place_unmatched`, `person_unmatched`, `taxon_ambiguous`, `table_parse_uncertain`, `date_ambiguous`.

## Правила

1. **Контракт меняет только владелец ядра.** Остальные присылают предложения (issue или PR с пометкой «contract»). Если меняется смысл модели, `docs/SPEC.md` правится в том же PR.
2. Порядок изменения: `observation.schema.json` → `schema.sql` → `openapi.yaml` / `export_columns.json` → фикстуры (`python contracts/gen_fixtures.py` или вручную) → `python contracts/validate.py` должен пройти.
3. Отсутствующее значение — это `null`, а поле всё равно присутствует. Значения не додумываются. Сомнительные значения получают флаг из enum `Flag`. Новые флаги — только через контракт.
4. `quote` — **дословная** подстрока `chunk.text`. При этом `chunk.text[quote_span[0]:quote_span[1]] == quote`: интервал полуоткрытый, отсчёт в символах Unicode (индексы Python str). Если цитату дословно найти не удалось, ставятся `quote_not_found`, `quote_span = null` и `bboxes = []`.
5. После изменения схемы БД пишется миграция (`ALTER ...`). `CREATE TABLE IF NOT EXISTS` не обновит уже существующую таблицу.

## Как валидировать

```bash
pip install jsonschema pyyaml          # обязательно
pip install pglast openpyxl            # по желанию: синтаксис SQL, сверка с xlsx
python contracts/validate.py
```

Чтобы применить `schema.sql` к настоящей БД, нужен `psql` (в `PATH` или в переменной `PSQL`) и подключение через стандартные переменные libpq: `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`. Скрипт создаёт временную БД `letopisi_validate_*`, применяет схему дважды (это проверка идемпотентности), загружает все фикстуры (проверяются FK и CHECK), проверяет trgm-поиск по кириллице и удаляет БД. Если psql или подключения нет, шаг пропускается с сообщением. Пример:

```bash
PSQL="/c/Program Files/PostgreSQL/17/bin/psql.exe" PGHOST=localhost PGPORT=5432 PGUSER=postgres python contracts/validate.py
```

Создать рабочую БД:

```sql
CREATE DATABASE letopisi TEMPLATE template0 ENCODING 'UTF8'
  LC_COLLATE 'ru_RU.UTF-8' LC_CTYPE 'ru_RU.UTF-8';   -- НЕ 'C', см. «Решения», п. 15
```

## Решения (сверх SPEC и там, где SPEC неполон)

1. **Идентификаторы** — целые `bigint GENERATED BY DEFAULT AS IDENTITY`. В фикстурах id заданы явно; после загрузки нужен `setval` (так делает `validate.py`).
2. **`person_ids`** — поле API. Колонки с таким именем нет: связи хранятся в `observation_persons(observation_id, person_id, ord)`, а `ord` задаёт порядок в `person_ids`. Если наблюдатель не найден в каталоге, его нет в `person_ids`, `observers_raw` сохраняется, ставится флаг `person_unmatched`. Для публикаций в `person_ids` попадают авторы-сотрудники.
3. **`bboxes`** — доли (0..1) от размеров **всей** страницы PDF, начало координат в левом верхнем углу. Для разворотов это доли всего разворота; `locator.half` указывает половину. Для сканов без OCR-координат `bboxes = []`.
4. **`locator.printed_page`** — печатный номер страницы фрагмента. **`printed_pages`** записи — строка для колонки «Ссылка на страницу», может быть диапазоном («76-77», «75-76»: таблица начинается на одной странице, строка стоит на другой).
5. **Нумерация страниц.** В книге 2020 номер страницы PDF совпадает с печатным. В книге 1995 страница PDF — разворот: левая печатная = 2·pdf_page − 4, правая = 2·pdf_page − 3. Это проверено по номерам на страницах PDF 36–45: например, PDF 40 = печатные 76 | 77, и там же таблица 45 ЗМУ из листа шаблона. В книге 1996 формула не проверялась.
6. **Шкала фенофаз растений** в легенде книги 2020 (стр. 76) содержит коды 1–16 и 10а/10б, а не только 1–12, как в SPEC. Все 18 кодов взяты в справочник, названия — из легенды дословно, плюс поле `bbch`. Коды 10а/10б пишутся **кириллическими** «а»/«б», как в книге и xlsx. «Зацветание» из табл. 7.10 и календаря природы сопоставлено с фазой 5 «начало цветения». Фенофазы животных получили латинские коды (`arrival`, `first_song`, `first_seen_spring`, `breeding`, `young`, `moult_summer`, `moult_winter`, `departure`).
7. **Год и даты.**
   - `obs_year` — год самого наблюдения. Например, столбцы 2018/2019 в табл. 7.10 или дата «20.10.19» в календаре 2020 года.
   - Флаг `year_outside_book` ставится **тогда и только тогда**, когда `obs_year` ≠ `documents.year`. Это проверяет validate.py.
   - Для публикаций `obs_year = pub_year`.
   - Если даты в цитате нет, то `date_raw`, `date_from`, `date_to` и `date_precision` — `null`, а `obs_year` берётся из контекста (год книги или столбца) и объясняется в `note`.
   - При `date_precision = day` выполняется `date_from = date_to`.
8. **Фильтр `doc_years`** (годы книг) — добавлен. `years` фильтрует по `obs_year`. Без `doc_years` запросы 3–4 («…за 1995, 1996 и 2022 годы») нельзя выразить: под «годами» там понимаются тома, а табл. 7.10 тома 2020 содержит даты 2018–2019. Запрос 2 («наблюдения за лосем в … годах») использует `years`. **«2022» в запросах xlsx считается опечаткой и заменяется на 2020** (как в SPEC); `/query/parse` сообщает о замене в `warnings`.
9. **Массивы в фильтрах.** `person`, `years`, `doc_years` — массивы в `SearchFilters` и строки через запятую в query (`style: form, explode: false`). Значения внутри массива объединяются по ИЛИ, разные фильтры — по И. Фильтр по датам срабатывает при пересечении интервалов.
10. **Записи `rejected`** не возвращаются `GET /observations` и `/export`, если `status` не задан явно.
11. **Ответы API.** В элементе списка (`ObservationListItem`) к записи добавлен `labels` с готовыми подписями: вид, место, фенофаза, люди, книга. `GET /observations/{id}` возвращает `{observation, chunk, section, document, edits}`. Ошибки имеют вид `{"error": {code, message, details}}`.
12. **PATCH.** `action = edit` → `edited`, `verify` → `verified`, `reject` → `rejected`. Каждый вызов пишет строку в `observation_edits`, где `changes = {поле: {old, new}}`, а также `status_before` и `status_after`. Менять можно только поля из `ObservationEditableFields`; источник (`document_id`, `chunk_id`, `locator`, `quote`, `quote_span`, `bboxes`) неизменяем.
13. **Расхождение с эталоном шаблона.** В листе `шаблон_животные` для ЗМУ 1995 стоит дата 31.03.1995, а в тексте учёт шёл 30–31 марта, и 31 марта — дата снегосъёмки. В фикстурах дата взята по тексту (`range` 1995-03-30…31) с флагом `date_ambiguous`. Значение маршрута 2 записано как «4.0» (в xlsx — «4»).
14. **Справочники.**
    - Принятые латинские названия — современные (`Rhododendron tomentosum`, `Cornus suecica`, `Neogale vison`), а книжные (`Ledum palustre`, `Chamaepericlymenum suecicum`, `Neovison vison`) записаны синонимами.
    - `gbif_key = null`: ключи не сверялись, их не выдумывали.
    - «Сметанникова» (1996) и «Сметанников» — разные записи каталога, не объединялись.
    - «Паз»/«Пасвик» и «Наутси»/«Наутсийоки» оставлены отдельными, как в каталоге.
    - Общие выражения «в заповеднике» привязываются к месту «Пасвик».
    - Координаты есть у Никеля, Заполярного и Раякоски: это `manual_approx`, точность около ±5 км. У остальных мест координат нет.
15. **pg_trgm и локаль.** При `LC_CTYPE = 'C'` pg_trgm не строит триграммы по кириллице: `show_trgm('лось') = {}`, и нечёткий поиск по-русски молча ничего не находит. Это проверено на PostgreSQL 17.5. Рабочую БД создавайте с `ru_RU.UTF-8` / `en_US.UTF-8` / `C.UTF-8` (Windows: `'ru-RU'`). Если локаль неподходящая, `schema.sql` выдаёт WARNING.
16. **`UNIQUE NULLS NOT DISTINCT`** в `persons` требует PostgreSQL 15+. Поскольку целевая версия — 16+, это допустимо. Схема проверена на 17.5.
17. **Фрагменты для фикстур.** Для книги 2020 chunk = страница целиком (`kind = page`), текст собран из `get_text("rawdict")` в порядке блоков. Пайплайн может резать мельче (`paragraph`, `table_row` и т. д.). Обязательно только одно: `quote` должна быть подстрокой своего chunk. Фрагменты 1995 года — ручная расшифровка (`text_source = manual`), а не OCR.
18. **`openapi.yaml`** ссылается на `observation.schema.json` внешними `$ref`, поэтому схема хранится в одном месте. Генераторам, которые не понимают внешние ссылки, сначала нужен бандл (`npx @redocly/cli bundle contracts/openapi.yaml -o openapi.bundled.yaml`). `openapi-typescript` и `datamodel-code-generator` работают с внешними ссылками напрямую.
19. **«Ссылка на страницу/-цы в документе»** = `printed_pages + ", том " + book_no`, как в SPEC (например, «76-77, том 2»). Для «Координат», «Численных показателей» и «Фенологической фазы» без значения выводятся «нет» / «нет» / «не фиксировалась» — так оформлены примеры шаблона. Подробные правила — в `export_columns.json`.
20. **Опечатка «Фенологическая фааза»** в заголовке шаблона исправлена на «фаза» в `export_columns.json` и `gold/template.csv`. Остальные заголовки перенесены дословно.
